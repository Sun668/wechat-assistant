# ClawBot 本地项目架构

## 执行路径

ClawBot 只接收绑定人的私聊请求。绑定人先用“项目列表”选择已登记的本地 Codex 项目；项目 ID 来自可信客户端回执。每个项目使用客户端登记的第一个（主）目录。收到的文档默认保存到该目录；`Config.toml` 的 `default_upload_path` 非空时则保存到指定的本地目录，后续消息仍在项目主目录启动官方 Codex CLI。腾讯原始消息、去重状态、任务、文件哈希、会话 ID 和发件箱保存在工作区的 `.wechat-assistant` 中。

`/upload-path` 是确定性配置命令，允许绑定人在未选择项目时查看、修改或清空全局收件目录，
不提交给模型。TOML 更新通过工作区内的文件锁和原子替换保存，保留其他配置与注释。
目录按收件事件固定到 `files.storage_root`；改配置、切换项目和重启不改写旧记录。
共享目录中的同名文件在数据库事务内跨项目预留名称，实际写入仍采用不可覆盖的原子链接。

每条消息由服务内的队列循环直接触发。所有项目的消息和文件接收工作单共用一条全局 FIFO 队列，同一时间只执行一项。接收时仅发送一次确认；前面有未完成工作时，在这条确认中说明排队。确认和最终结果在正文中标出对应的原问题；当前 iLink 出站通道没有经过验证的原生引用框能力。执行中不发送启动、资料就绪或心跳通知；完成后发送结果，失败时发送失败通知。项目指令由确定性路由处理；其余所有者文字先通过独立、只读的 Codex CLI 会话判断普通、定时或需澄清的意图，不依赖关键词列表。普通请求再把原文和已收文件清单交给既有项目会话，同一任务使用准确的 thread ID 续聊；分类会话不占用该 thread ID。网关不根据已送达消息拼接另一套模型记忆。Codex 使用主机官方状态目录中的登录、会话和本地记忆配置。模型推理可使用 OpenAI 云端，项目文件不会因此自动上传到 ChatGPT 云端 Sources。

所有者的口语化定时请求由只读 Codex CLI 解析为时间、重复方式和工作内容，经过严格校验后由 macOS `launchd` 注册触发。日历任务使用 `StartCalendarInterval`；相对时间与固定间隔循环任务保存创建时的锚点，并使用 `StartInterval` 唤醒后核对时间槽。`launchd` 只运行系统 `curl`，携带计划专属令牌请求本机网关；实际入队由已有工作区进程完成，避免独立 Python 进程缺少工作区访问权限。触发器仅把原始所有者消息 ID、项目 ID 和时间槽绑定的工作单放入数据库；现有项目队列使用订阅登录的官方 Codex CLI 执行，结果由唯一 ClawBot 发件箱发送。计划和每次触发都以数据库唯一键去重。CLI 没有桌面 Scheduled 管理接口，因此计划由 `launchd` 管理。

## 安全边界

- 项目主目录缺失、变化或与其他项目重叠时，任务标为失败、暂停队列，且不提交给 Codex。
- 文件在接收时固定项目、目录、名称和哈希；执行前与提交结果前再次校验。
- 不确定的 Codex 提交、发送或重启恢复均暂停，等待操作者核对，不自动重试。
- 重启后自动处理排队任务和可确认未提交的任务；若原生结果文件完整且会话 ID 已绑定，直接恢复结果。已经开始写入项目而结果不明的任务继续等待核对。
- 只有绑定人的精确指令可发送文件；所有外发由唯一发件箱写入者完成。
- 引用必须匹配准确消息 ID 或完整随机标记，不能凭摘要猜测。
- 无微信联系人监听、联系人回复、GUI 控制或审批流程。

## 模块

| 模块 | 职责 |
| --- | --- |
| `adapters/ilink`、`ilink_media` | 绑定人私聊收发与文件下载 |
| `adapters/codex_projects`、`projects/catalog` | 官方 App Server 只读项目目录连接、分页、原子刷新与失败回退 |
| `projects/router` | 确定性项目、任务、文件和引用路由 |
| `projects/storage` | 原始事件、不可变文件快照、队列和发件箱 |
| `projects/bridge` | 进程内工作单领取、精确会话绑定和结果校验 |
| `projects/execution` | 全局顺序执行与证据复核 |
| `projects/local_engine` | 官方 Codex CLI 的本机登录检查、执行与续聊 |
| `projects/schedule_spec` | 口语化时间解析结果校验 |
| `projects/local_schedules` | launchd 计划注册与触发工作单 |
| `projects/delivery` | 向绑定人发送公开结果，隔离不确定写入 |
| `projects/runtime`、`api` | 常驻服务、状态检查和操作者管理接口 |

旧客户端定时任务和 `native-relay` 接口已删除。现存数据库中的历史项目、消息和文件记录继续保留；不把历史草稿当作已发送事实。
新计划属于本机 `launchd`，不会出现在桌面 Codex Scheduled 中；每次触发建立一条本机 Codex 工作单。

## 验证范围

“项目列表”自动刷新已有模拟测试覆盖认证、去重、回声抑制、分页、超时、并发、重启、
移除项目的历史保留与失败回退。本机官方 CLI 0.165.0-alpha.1.2 已完成不调用模型、
不发微信的真实 `initialize` / `project/list` 只读探针；实际微信收发链路未在本次验收。

模拟测试覆盖全局排队、重启、文件证据失效、精确引用、回声抑制、launchd 计划创建与触发。此前真实 Codex CLI 已在隔离目录完成两轮同会话执行，并通过模拟微信传输收到两条已发送回执。引用确认的出站结构仅经过模拟验证；未向真实微信联系人发送测试消息。

CLI 新建的会话可由客户端按 ID 读取，但目前不自动出现在客户端项目会话列表。跨新会话的记忆效果尚未实测。
订阅定时路径的计划入队和微信回传经过模拟测试；旧版真实 `launchd` Python 触发器卡于解释器初始化且未入队。新版系统 `curl` 触发器经过无微信发送的真实 `launchd` 探针验证，完整真实定时回传尚未验收。
